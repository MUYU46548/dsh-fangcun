**跑完一整晚，想知道这些会话到底烧了多少 token，还得自己开方寸一个月一个项目去核对。**

dsh-fangcun 是 [方寸（tegula）](https://github.com/MUYU46548/fangcun) 任务看板的 [DSH](https://github.com/deepseek-ai/deepseek-harness) 插件。它做两件事：把 DSH 每一轮的 token 用量自动记回方寸账本，以及把方寸里没做完的卡显示在 DSH 界面右上角（位置可改）。不需要复制粘贴，不需要手记。

本项目是方寸的**附属项目**，需要先装好方寸才能用；它是 DSH 插件，不能单独运行。本项目使用 AI 辅助开发。

## 装进 DSH

**前提**：Windows 上的 DSH 桌面版（0.2.0-rc.2 或更新），并且方寸正在运行（插件靠它的命名管道取数据）。

1. 打开 DSH 的「插件 → 添加插件」。
2. 在「包名或地址」里填入 `dsh-fangcun@0.3.0`，「安装源」保持默认。
3. 安装完成后**含托盘完全退出 DSH 再打开** —— 插件不进热更，不重启就不会加载。

也可以走 GitHub Release（离线或 npm 不可用时）：

```text
https://github.com/MUYU46548/dsh-fangcun/releases/download/v0.3.0/dsh-fangcun-0.3.0.tgz
```

或者用命令行（两种源任选）：

```powershell
dsh plugin --profile desktop add dsh-fangcun@0.3.0
# 或
dsh plugin --profile desktop add https://github.com/MUYU46548/dsh-fangcun/releases/download/v0.3.0/dsh-fangcun-0.3.0.tgz
```

> 建议把安装和更新都交给 DSH 里的 Agent 处理：它自己能装、能查 health、能判断装没装好。
> 插件更新由 `dsh-plugin-updates` 负责 —— 只要本仓库发了新的 Release，它就能认出来，不需要你再手工下载。
> npm 与 GitHub Release 是**同一份代码的两条分发通道**，不是两个版本。

**装完怎么确认？** 浏览器打开 `http://127.0.0.1:<DSH 端口>/fangcun/health.json`，应当看到 `"ok": true` 与 `"version"`（等于你装的那一版）。端口从 DSH 窗口地址里取。

## 装完你会看到

### 右上角多了一个小圆点（四个角随便挑）

点开就是方寸里**没做完**的卡（完成和驳回的不算，状态空着算没做完）。点条目复制「卡号 + 标题」，粘进对话就能开工；点「打开看板」直接去方寸本体看（方寸的看板服务没起时，这个入口不会出现，避免给出打不开的地址）。

- **角标会说人话**：`方寸 · 130 · 在办 3 · 待拍板 2` —— 在办是方寸里状态「进行中」的卡，
  待拍板是「待验收 / 待审批」（在等你点头的）。两个数都是**方寸自己写的状态**数出来的，插件不另判优先级；
- **面板顶部有「本次在办」**：你（或 agent）最近一次动过的那张卡，单独一行、带底色，
  点它复制「卡号 + 标题」。卡号只从方寸工具调用的参数里取 `id` 这一个字段；
- 跟着系统深浅色走，深色模式下不是白底；
- 默认收起，不挡 DSH 自己的控件；展开状态会记住；
- **位置自己挑**：面板底部有「位置：右上 右下 左下 左上」，点一下就地挪过去，选择会记住。
  默认**右上角** —— 右下角留给别的挂件（比如那只鲸鱼），插件之间不抢同一块地方；
- **也能拖，拖到哪就停哪**：右键角标 → 「拖动：已锁定」点成可拖动（面板里也有同一个开关），
  然后按住圆点拖到任意位置，松手就定住、下次打开还在那儿（不会自己弹回角上）。
  拖到窗口边会被夹在可见区内，不会拖丢。**默认锁着**，因为圆点主要是用来点开面板的，
  手一抖就被拖走比拖不动更烦；锁着时硬拖会提示一句"拖动已锁定"，不会一声不响；
- **右键还有菜单**：解锁拖动 / 摆到四角 / 刷新 / 打开看板 / 收起挂件，都在右键里。
- 嫌它碍事就点「收起挂件」—— 会缩成一个带「方寸」字样的小胶囊，点一下还能回来。

### 设置里能直接改（0.7.0 起）

DSH 的**设置**面板里多了一节「方寸」（和其它插件的设置页一样，不是右键菜单）：

- **状态**：方寸装没装、连没连、数据根从哪来、当前管道、项目范围、未完成 / 在办 / 待拍板；
- **连接设置**：数据根、管道、项目范围三项，留空 = 自动探测 / 环境变量 / 全部项目。
  保存写进 DSH 的 profile（不是插件自己的配置文件），插件会重启一次让新值生效；
- **挂件**：显示 / 隐藏、四角一键摆位；点完立刻作用到页面上的挂件，不用刷新。

> 设置页和挂件共用同一份 `localStorage`（位置、锁定、显示），所以两边看到的是一致的。
> 设置写不进去时页面会明说原因（宿主没有 `configEditor` 服务），不会假装保存成功。

### 没装方寸本体？它会直接告诉你

插件会看一眼这台机器上有没有方寸桌面版的**装机痕迹**（数据目录、开始菜单/桌面快捷方式、
安装目录等），只看文件，**不跑进程、不发网络请求**。没有的话：

- 右上角角标写「方寸未安装 · 去下载」，点开面板里有下载地址
  （[方寸 Releases](https://github.com/MUYU46548/fangcun/releases/latest)，Windows 安装包）；
- 提示词里那一行现状也会变成「方寸 · 未安装」，agent 会照着说，而不是假装查到了待办。

三种情况分得很清楚，别被一句"未连接"糊弄：

| health 里 | 含义 | 你该做什么 |
|---|---|---|
| `fangcun.installed: false` | 这台机器还没有方寸桌面版 | 去上面那个 Releases 页装一个 |
| `installed: true` + 挂件显示「未连接」 | 装了但没在跑（或管道名不对） | 打开方寸；还不行就看 `FANGCUN_MCP_PIPE` |
| `installed: true` + 数字正常 | 一切正常 | 不用管 |

### agent 会被提醒用方寸

插件往系统提示词里放两样东西（0.3.0 起）：

- **规则段**：开工先查（`list_tasks`）、收工回写（`update_task` / `move_status`）、
  新问题建卡（`create_task`）、失败要说；并写清**闲聊不用查**，免得每条消息都去翻看板。
- **一行现状**：`全部项目 · 未完成 114 张`。只有一行，不列标题、不分组 ——
  那是噪音；细节去方寸看。方寸没开就写「方寸 · 未连接」，本机没装就写「方寸 · 未安装」。
  ⚠ 给 agent 的这一行**故意不带时间戳**：DSH 的运行时上下文逐字比较文本，带上「截至 HH:MM」
  会让它每分钟都判定“变了”、每分钟追加一条提醒。健康检查那份仍带时间（那里才需要“最后一次成功是什么时候”）。

这两样都只读方寸的 MCP 接口；`健康检查` 的 `prompt` 一格会告诉你规则段到底注册上没有。

### agent 能直接调方寸了（0.4.0 起）

规则段之前只是"提醒"，模型听不听全靠自觉。0.4.0 补上了真正的工具，
模型可以自己查卡、读卡、写卡 —— 不用你中转：

| 工具 | 做什么 |
|---|---|
| `fangcun_context` | **一次拿到项目背景**：章程四节（使命/目标/场景/边界）+ 最近有效决策 + 手上还有的活 + **固定记忆核心（≤800 字）** + 上次做到哪 |
| `fangcun_tasks` | 列未结的卡（只读） |
| `fangcun_card` | 读某一张卡的正文（只读） |
| `fangcun_write` | 新建 / 修改 / 改状态（`create` / `update` / `move`） |

**为什么 `fangcun_context` 是最重要那一个**：在这之前，模型只知道"有方寸这个看板"，
不知道**这个项目要变成什么**——于是它照着通用常识干活。这是"AI 写代码没全局意识、
天天乱改、忘记东西"的直接对策：**先给项目的灵魂，再让它动手。**

章程哪一节没人写，它会**明说「真没写」**，并列出缺哪几节 —— 不替项目编目标。

0.7.2 起只注入**固定记忆核心** `memory/core.md`（由方寸的钉住 claim 生成、硬上限 800 字、只放编号与一句话）；
完整事故/教训留在归档，**不自动注入**，只报「另有 N 条」，要细节模型自己
`memory_search` / `memory_read`。这是抄 Letta 的 core memory + Claude memory tool 的
just-in-time —— 不是把几十万字或动态 top-5 每次都塞进上下文。
**记忆开关关闭时**会明说「记忆核心（已关闭）」，不会说成「core.md 没写」。
拉不到核心时它会明说「没拉到，这不等于没踩过坑」，不会说成"这个项目很干净"。

几条刻意的设计：

- **只白名单**：`fangcun_write` 只认 `create` / `update` / `move` 三个动作，
  不能拿它转发任意方寸工具 —— 那等于给模型开一个万能后门。
- **参数不全就报错，绝不猜**：没说标题就不建卡，没说目标状态就不移卡。
- **输出有界**：列卡最多 30 条、单卡正文最多 4000 字，超了会明说"还有多少没显示"。
  上下文是共用的，不能一次塞满。
- **不谎报**：方寸没开时，读工具回空列表、写工具明确回失败原因，
  不会出现"它说写好了其实没写"。
- **和 MCP 断开无关**：这三个工具走插件自己那根管道。就算 DSH 里的
  fangcun MCP 客户端掉线了（会显示 `mcp__fangcun__*` 工具不见了），它们仍然可用。

`健康检查` 的 `tools` 一格会告诉你注册上没有：`registered` 为 `true` 才算真装上。
移到「待验收」就停手，等你自己签 `完成` —— 插件不会替你把卡关掉。

### DSH 升级了怎么办：它只提醒，不会自己消失

DSH 还在 developer preview，**升级很频繁**。这里有一个容易踩的坑：
如果插件在 `package.json` 里写了"只支持 0.2.x"，那么 DSH 一升到 0.3，
**宿主会把这个插件整个跳过**——挂件、记账、工具全没了，界面上只显示"没装"，
而且**不会告诉你原因**。

所以现在 `engines.dsh` **只写下限、不写上界**：DSH 升级后插件照常加载，
能用的部分继续用。同时插件每次启动会体检六项宿主能力，结论写在 `health.compat`：

```json
"compat": {
  "capabilities": { "webServer": "ok", "tools": "ok", ... },
  "warnings": [],
  "summary": "全部 6 项宿主能力正常"
}
```

哪一项变了（`degraded`）或没了（`missing`），`warnings` 会用一句话说清哪块受影响。
**这是"只提醒"**：插件不退出、不罢工，你能用的东西一样不少，只是知道哪块要修。

### 它自己记账：agent 到底调没调方寸

`$DSH_HOME/dsh-fangcun/tools.jsonl` 里记着方寸工具被调用的时间、会话、轮次与名字
（**不记参数**，参数里可能有你的私事）。另外 `turns.jsonl` 每轮一行，记的是**顺序**：

- 这一轮的第一次工具调用是不是方寸（②7「开工先查」）；
- 这一轮**改过文件却没有回写方寸**（②8「收工回写」）；
- 这一轮只查了方寸、别的没动（②10「闲聊别查」的可疑信号）。

`/fangcun/health.json` 的 `proof.turns` 直接给出这四个数，不用人翻日志，也不靠模型自述。

### 账本自己长出来

每轮对话结束，这一轮用掉的 token 自动记进方寸账本，带 `origin=external` 标记，和方寸自己花的钱分开。方寸没开着也不丢：记录先攒在本地，60 秒后重试。

这一轮的 `note` 里还会带上**在办那张卡的卡号**（`card=<卡号>`，只取参数里的 `id`）——
方寸那边可以据此把 token 归到卡上（"这张卡花了多少"）。卡号太长放不进 120 字上限时就不带，
**绝不写半截卡号**（半截 id 会归到一张不存在的卡）。

**只报 token，不报金额。** DSH 只给 token 数，没有供应商报价；自己按价目表算出来的是估算，塞进标着"供应商报价"的字段里就是让账本说假话。要折算成钱，请在方寸侧按自己的口径做。

## 它不做什么

| 不做 | 为什么 |
|---|---|
| 不读方寸的 `task-data/*.md` | 只走方寸对外的 MCP 接口，方寸改数据格式不用重发插件 |
| 不改方寸的任何数据（除了你让模型写的那一次） | 插件自己从不主动写；只有模型调用 `fangcun_write` 且参数齐全时才动，且只按参数走、不顺手补步骤 |
| 不替你把卡关掉 | `fangcun_write` 移到「待验收」就停；`完成` / `驳回` 永远是你点的 |
| 不往上下文塞待办列表 | 只放**一行**「未完成 N 张」；把十几个项目的卡全塞进去是噪音，不是引导 |
| 不上传对话内容 | 报给方寸的只有：会话短名、轮次、token 数、在办卡的卡号；工具参数只白名单取 `id`，其余一个字符都不读 |
| 不发任何网络请求 | 只连本机的命名管道 |
| 不碰 DSH 的配置 | 只声明自己的 5 条路由（健康检查 / 挂件脚本 / 页面自证 / 待办接口 / 设置）+ 8 个模型工具；设置页只改**本插件自己那一行**的 config（`configEditor`），不碰别的插件 |
| 不让局域网访问 | 路由只回本机请求，其他来源一律 403 |

插件本身零依赖，只用 Node 内置模块。

## 配置

**优先用 DSH 设置 → 方寸**（0.7.0 起）。下面三个环境变量还在，且优先级低于设置页，
是给多机部署、非默认路径或单项目口径用的：

| 变量 | 作用 | 默认 |
|---|---|---|
| `FANGCUN_DATA_DIR` | 方寸数据根（认不出时 health 里 `dataDir` 会是空串） | 读 `%APPDATA%\方寸\data-dir.json` |
| `FANGCUN_MCP_PIPE` | 方寸 MCP 管道路径 | Windows `\\.\pipe\tegula-mcp` |
| `FANGCUN_PROJECT` | 提示词那行只统计某个项目（填方寸里的 project id，如 `sitian`） | 空 = 全部项目 |

## 出问题了

| 症状 | 先看 | 怎么办 |
|---|---|---|
| 装完界面没变化 | `health.json` 是否 200 | 没重启，或插件没进 profile；**含托盘完全退出**再开 |
| 设置里看不到「方寸」 | `health.client.available` | `false` = 清单没被重读：`plugin_manager` 重启一次条目（`include:dsh-fangcun`）；`true` = 客户端半已进页面，打开设置面板看 |
| 圆点上写着「方寸未连接」 | 方寸是否在跑 | 启动方寸；点一下圆点可重试 |
| 账本里没有记录 | `health.usage` 的 `outboxPending` / `lastError` | 有积压 = 方寸没开或管道名不对；`lastError` 会写明原因 |
| 看板入口不见了 | 方寸看板启动过没有 | 插件按方寸自己记的端口给链接，没记过就不显示，不会给你一个打不开的地址 |
| 界面底部出现**一大段纯文本**（「方寸 · N」跟一串待办） | 0.2.0 的样式 bug | 0.3.0 已修：样式表没挂进页面，挂件退化成正文。现在默认右上角一个小圆点 |
| agent 没有先查方寸就开工 | `health.json` 的 `prompt.rules` | `true` = 规则段注册了（模型看得到）；`false` = 宿主没有 `systemPrompt` 服务，看 `prompt.error` |
| 上下文里那行写着「方寸 · 未连接」 | 方寸在不在跑 | 插件只读缓存，方寸恢复后 60 秒内自动变；也可看 `prompt.line` |
| 小圆点挡住了别的东西 | 挂件位置 | 解锁「拖动」后直接拖到想要的位置（松手就定住）；面板底部「位置」四选一可以一键摆到四个角 |
| 拖不动 / 一点就开面板 | 「拖动」是「已锁定」 | 面板里点一下「已锁定」变成「可拖动」，再按住圆点拖；拖完可以再锁回去 |
| 拖完又弹回角上 | 0.3.0 之前的"吸角"行为 | 0.3.0 起改成自由摆放：拖到哪就停哪，位置存 `localStorage`，刷新还在（四角按钮仍是一键摆位） |

排查都以 `health.json` 为准 —— 它报的是插件能自证的事实，不猜。

## 文档与开源

[更新记录](CHANGELOG.md) · [MIT 许可证](LICENSE) · [方寸本体](https://github.com/MUYU46548/fangcun)

本插件的本地数据都在 `%USERPROFILE%\.dsh\dsh-fangcun\`：`sent.jsonl` 是已上报的记录，`outbox.jsonl` 是还没发出去的积压，`tools.jsonl` 是方寸工具调用的自证日志（只记时间/会话/轮次/工具名，不记参数）。删掉它们不会影响方寸里的任何数据。

随着 DSH Windows 桌面版的版本变化，本插件可能不再适用。作者会尽快跟进新版 DSH，但不为可用性提供担保。
