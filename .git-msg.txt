feat(0.7.8): 四个提议口 + 派单权限可配

对应方寸 6dc0dc1（0.7.9）与 2026-11-23 问卷《方寸-决策机制三岔路》的 K1 / K3。

## K3（答案 A：四个口一起补）

`fangcun_write` 从 3 个 action 扩到 **7 个**：
`create` / `update` / `move` / `qn_propose` / `decision_propose` /
`stage_plan_propose` / `smap_propose`。

这是「AI 从不拿决策问我」的**机器真因**：技能卡 fangcun-bridge ①.9 早写着
「有 ≥2 件要拍板 → 用 qn_propose 出卷」，而工具表里没有这个口。
实测插件日志 500 条 / 14 个会话，问卷类调用 **0 次** —— 技能教了，工具没有。

四个口**都只能落草稿态**，谁都不能自批（这是它们存在的正当性前提）：
- qn_propose：每题 id / ≥2 选项 / 每选项写代价 d / 每题写验收线 line，缺一项当场抛
- decision_propose：只落「待审批」；传 status 直接拒（不是悄悄降级）
- stage_plan_propose：三块（技术方案/照抄点/判据）缺一不可，判据必须带
  cmd:/str:/num:/file: 前缀
- smap_propose：不碰 policies/，mapText 必须带 `最后核实：YYYY-MM-DD`

参数在插件侧先校验一遍：让模型一次写对，而不是撞墙后拿报错返工。
方寸侧仍是唯一真源，会再判一次。

⚠ 名字是 `decision_propose` 而不是 `decision_record` —— 后者 2026-11-03 被
**明确移除**过，理由是「要开口必须先有『AI 只能落待审批』的设计」。现在那个设计
在方寸侧落地了（决策第四态「待审批」），名字也改成说出它只能提议。

## 第 3 条：派单默认权限可配

新增设置项 `dispatchPreset`。答案：**权限档就是 Agent 预设档**（agentPreset），
它决定派单会话挂哪些工具（含文件/终端写权限）。所以"改默认权限"= 决定这一单用哪一档，
**不用碰 DSH 的 Agent 预设本体**（暮雨原话「DSH的Agent预设太复杂，别去碰它」）。

优先级：设置页显式指定 > 宿主当前默认档 > 不传（宿主兜底）。
留空 = 跟宿主默认走（推荐，也是出厂行为）——不是"最小档"，那样是静默降权。
留空判据写 `!preset.trim()`，不是 `preset === undefined`。
